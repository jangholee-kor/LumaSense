# Smart Monitor Controller 개발 계획서

**프로젝트 버전:** 1.0<br>
**대상 운영체제:** Windows 11 25H2 이상<br>
**개발 방식:** Codex 기반 자동 구현 및 테스트<br>
**개발 언어:** Python 3.12+ / ESP-IDF C<br>
**프로젝트 목표:** 조도 기반 밝기 자동 조절 및 인체 부재 시 모니터 자동 절전

---

## 1. 프로젝트 개요

Windows PC에 연결된 외부 조도센서와 mmWave 인체 감지 레이더를 이용하여 모니터를 자동으로 제어하는 시스템을 개발한다.

Windows 프로그램은 시스템 트레이에 상주하며, ESP32-S3에서 전달되는 센서 데이터를 받아 모니터의 밝기와 절전 상태를 제어한다.

**최우선 설계 원칙**

- 장시간 움직이지 않고 앉아 있는 사용자를 감지할 것
- 조명 변화에는 빠르게 반응하되, 밝기 변경은 부드럽게 수행할 것
- 사람이 자리를 떠나면 화면만 끄고 PC는 계속 작동할 것
- 사용자가 돌아오면 자동으로 화면을 깨울 것
- 소프트웨어 또는 센서 오류로 인해 화면이 반복적으로 꺼지지 않도록 할 것
- 모든 설정을 Windows GUI에서 변경할 수 있도록 할 것

## 2. 하드웨어

### 2.1 MCU

- ESP32-S3 N16R8 개발보드
- USB Serial/JTAG 인터페이스 사용
- ESP-IDF 프레임워크
- USB 상시 전원
- Wi-Fi 및 BLE는 초기 버전에서 사용하지 않음

### 2.2 조도센서

- BH1750
- I²C 통신
- Continuous High Resolution 모드
- 측정 주기 약 200ms
- Lux 값 USB 전송

### 2.3 인체 감지 센서

- HLK-LD2412
- UART 통신
- 움직임 및 정지 상태의 인체 감지
- 거리 및 에너지 데이터 수집
- 감지 거리와 민감도 설정 가능
- 최초에는 약 0~1.5m 범위로 설정하고 실측값에 따라 조정

### 2.4 모니터

- Philips 32M2N8900 OLED
- DDC/CI 밝기 제어
- Windows 디스플레이 절전 기능
- HDR/SDR 모드에서의 동작 차이 검증 필요

### 2.5 배선

ESP32-S3의 GPIO는 실제 개발보드의 회로도 확인 후 지정한다.

BH1750은 I²C, LD2412는 UART에 연결한다. 모든 센서의 전원 전압, 신호 레벨, UART 핀 배열을 데이터시트에서 검증한다.

USB Serial/JTAG에 사용하는 GPIO19/20은 다른 용도로 할당하지 않는다.

## 3. Windows 애플리케이션

### 3.1 기술 스택

- Python 3.12 이상
- PySide6: Windows GUI 및 시스템 트레이
- pyserial: USB CDC 통신
- ctypes / pywin32: Windows API 호출
- subprocess: Twinkle Tray CLI 실행
- JSON: 설정 저장
- logging: 로그 시스템
- pytest: 자동화 테스트
- PyInstaller: 실행 파일 패키징

### 3.2 프로그램 구조

프로그램은 다음 독립 모듈로 구성한다.

1. SerialManager: USB 장치 검색, 연결, 데이터 수신 및 재연결
2. SensorManager: BH1750/LD2412 데이터 검증 및 처리
3. BrightnessController: 조도 기반 목표 밝기 계산
4. PresenceController: 인체 감지 상태와 부재 타이머 관리
5. DisplayController: 밝기 및 Windows 절전 명령 실행
6. SettingsManager: 설정 로드, 저장, 검증
7. MainWindow: 설정 GUI
8. TrayManager: 시스템 트레이 및 빠른 제어
9. Diagnostics: 로그, 센서 상태, 오류 진단

GUI 스레드에서 시리얼 읽기나 DDC/CI 명령을 동기적으로 실행하지 않는다.

## 4. ESP32-S3 펌웨어 요구사항

### 4.1 센서 데이터 수집

- BH1750 주기 측정
- LD2412 UART 수신
- 레이더 프로토콜 파싱
- 패킷 체크섬 및 길이 확인
- 센서 통신 오류 검출
- 주기적 상태 전송

### 4.2 통신 프로토콜

초기 버전은 개행으로 구분된 JSON Lines 프로토콜을 사용한다.

예시:

```json
{
  "ver": 1,
  "seq": 1234,
  "uptime_ms": 258000,
  "lux": 125.5,
  "presence": true,
  "moving": false,
  "stationary": true,
  "distance_cm": 67,
  "sensor_ok": true
}
```

필드별 유효성 검증을 수행하며, 센서값을 읽지 못하면 임의의 0이나 false 대신 오류 상태를 전달한다.

LD2412에서 제공하는 실제 데이터 항목은 제조사 프로토콜 문서에 따라 조정한다.

PC와 MCU 간 통신은 추후 설정값 변경 명령도 수신할 수 있도록 양방향 구조로 설계한다.

### 4.3 펌웨어 개발

Codex에서 아래 작업을 자동 실행할 수 있도록 스크립트를 제공한다.

- ESP-IDF 환경 확인
- 빌드
- USB 자동 다운로드
- 장치 리셋
- 시리얼 로그 저장
- 오류 분석

USB Serial/JTAG가 연결된 포트를 사용한다. PC 프로그램과 플래시 도구가 동일한 COM 포트를 동시에 점유하지 않도록 한다.

## 5. 조도 기반 밝기 제어

### 5.1 동작 개요

BH1750에서 수신한 Lux 값을 바탕으로 목표 모니터 밝기를 계산한다.

고정된 밝기 단계뿐 아니라 사용자가 지정한 조도-밝기 곡선을 지원한다.

초기 설정 예시:

| 조도 | 목표 밝기 |
|---|---|
| 0 lux | 10% |
| 5 lux | 15% |
| 30 lux | 25% |
| 100 lux | 40% |
| 300 lux | 60% |
| 500 lux | 75% |
| 1000 lux | 85% |

설정값 사이에서는 선형 보간을 적용한다.

추후 로그형 조도 매핑을 지원할 수 있도록 계산 로직을 독립시킨다.

### 5.2 반응 알고리즘

- 센서 측정: 약 200ms
- 짧은 EMA 필터 적용
- 빠른 조도 변화는 즉시 목표값에 반영
- 1~3초 사이의 밝기 전환
- 불필요한 1% 단위 반복 변경 억제
- 밝기 상한/하한 설정
- DDC/CI 명령의 과도한 반복 방지

밝기 변경 간격은 모니터의 명령 처리 속도를 측정한 뒤 결정한다.

### 5.3 수동 밝기 조절

사용자가 트레이 슬라이더나 단축키로 밝기를 변경할 수 있어야 한다.

수동 조절 시 자동 밝기를 일정 시간 중단하는 기능을 제공한다.

초기 설정: 15분 일시 중단.

### 5.4 DDC/CI 연동

1차 구현은 Twinkle Tray CLI를 사용한다.

- 모니터 목록 조회
- 대상 모니터 식별 및 선택
- 절대 밝기 변경
- 실행 오류 확인

모니터 번호보다 안정적인 식별자가 사용 가능하면 해당 식별자를 우선한다.

향후 Twinkle Tray 의존성을 제거할 수 있도록 BrightnessBackend 인터페이스를 구현한다.

## 6. 레이더 기반 존재 감지

### 6.1 기본 조건

센서는 모니터 하단 중앙에 배치하며 사용자의 상체를 향하도록 설치한다.

사용자는 약 60cm 앞의 의자에 앉고, 좌우 이동 범위는 작다고 가정한다.

### 6.2 감지 알고리즘

레이더의 존재 여부를 기본 판단값으로 사용하되, 움직임·정지 상태와 에너지 데이터를 진단용으로 기록한다.

초기 정책:

- 인체 감지 시 화면 ON 유지
- 일시적인 감지 누락은 무시
- 30초 연속 미감지 시 화면 OFF
- 재감지 시 즉시 화면 ON 요청
- 최근 Windows 키보드/마우스 입력이 있다면 화면 OFF 보류

### 6.3 상태 관리

다음 상태 머신을 구현한다.

- PRESENT: 사람 감지 중
- MAYBE_ABSENT: 미감지 타이머 진행
- ABSENT: 부재 확인
- DISPLAY_OFF: 화면 절전 상태
- RECOVERING: 화면 복귀 요청
- SENSOR_ERROR: 레이더 또는 USB 연결 오류

중복 화면 끄기 명령과 반복 복귀 명령을 방지한다.

### 6.4 오류 처리

센서 연결이 끊기거나 레이더 데이터가 일정 시간 수신되지 않으면 사용자를 부재 상태로 처리하지 않는다.

대신 자동 화면 OFF 기능을 일시 중단하고 오류를 표시한다.

프로그램 시작 직후에는 일정 시간 센서 안정화 과정을 거친다.

## 7. Windows 화면 OFF/ON

### 7.1 기본 제어 방식

Windows `WM_SYSCOMMAND / SC_MONITORPOWER` API를 사용하여 디스플레이 절전을 요청한다.

PC 시스템 절전, 최대 절전, 로그아웃 및 잠금은 수행하지 않는다.

### 7.2 화면 복귀

Windows API를 통한 화면 복귀 요청을 우선 시도한다.

대상 모니터 및 그래픽 드라이버에서 정상 동작하지 않으면 안전한 대체 복귀 경로를 구현한다.

실제 입력 시뮬레이션을 사용해야 할 경우 사용자 입력이나 실행 중인 애플리케이션에 영향을 주지 않는 방법을 우선 검토한다.

### 7.3 안전 제한

DDC/CI VCP 0xD6을 통한 전원 OFF는 기본 기능에서 제외한다.

완전 전원 OFF 이후 소프트웨어로 다시 켤 수 없는 위험이 있기 때문이다.

Windows 절전과 복귀 동작이 검증된 이후에만 선택적 실험 기능으로 제공한다.

## 9. 개발 단계

### Phase 1 — Windows 제어 기능 검증

센서나 MCU 연결 없이 시작한다.

- PySide6 기본 GUI
- Twinkle Tray 실행 파일 검색
- 모니터 목록 확인
- 밝기 20%, 50%, 80% 설정
- Windows API 화면 OFF 시험
- 화면 자동 복귀 시험

**완료 기준:** 실제 Philips 모니터에서 밝기 제어와 화면 절전·복귀가 동작하며, 결과를 기록한다.

### Phase 2 — ESP32-S3 펌웨어

- ESP-IDF 프로젝트 생성
- USB CDC/JTAG 설정
- BH1750 드라이버
- LD2412 UART 수신 및 파싱
- JSON Lines 프로토콜
- 자동 빌드/플래시 스크립트

**완료 기준:** Windows에서 10분 이상 센서 데이터를 정상 수신한다.

### Phase 3 — Windows 시리얼 통신

- COM 포트 탐색
- 연결 및 재연결
- JSON 데이터 파싱
- 오류 처리
- 실시간 GUI 표시
- 센서값 기록

**완료 기준:** 연결 해제와 재연결 이후 프로그램 재시작 없이 정상 복구한다.

### Phase 4 — 자동 밝기

- Lux-밝기 매핑
- EMA 필터
- 밝기 전환
- Twinkle Tray 연동
- 수동 밝기 조절
- 밝기 프로필 저장

**완료 기준:** 조명 ON/OFF 시 빠르게 반응하고 잦은 밝기 변동 없이 동작한다.

### Phase 5 — 자동 화면 절전

- 레이더 존재 감지
- 부재 타이머
- Windows 화면 OFF
- 재감지 시 화면 복귀
- Windows 입력 상태와 연동
- 오류 발생 시 Fail-safe 처리

**완료 기준:** 장시간 착석 중 오작동으로 화면이 꺼지지 않으며, 자리 이탈과 복귀가 정상 반영된다.

### Phase 6 — 안정화 및 배포

- 장시간 테스트
- 이벤트 로그
- CPU/메모리 사용량 점검
- 예외 처리
- PyInstaller EXE 빌드
- 자동 실행 등록
- 사용자 매뉴얼 작성

**완료 기준:** 최소 24시간 연속 운용에서 프로그램 비정상 종료가 없고 핵심 제어 기능이 유지된다.

## 10. 테스트 계획

### 자동 테스트

- 조도 매핑 경계값
- 센서 패킷 손상
- 시리얼 연결 해제
- 레이더 감지 누락
- 화면 OFF 타이머
- 센서 오류 시 Fail-safe
- 설정 저장 및 로드
- 모니터 제어 백엔드 오류

### 실사용 테스트

1. 낮에 자연광만 있는 환경
2. 저녁에 형광등을 켠 환경
3. 밤에 조명을 모두 끈 환경
4. 30분 동안 움직임 없이 착석
5. 30초 이상 자리 비움
6. 자리 복귀 후 화면 자동 ON
7. USB 분리 및 재연결
8. Windows 잠금 및 로그온
9. 모니터 HDR/SDR 전환
10. 24시간 연속 작동

실측이 필요한 항목은 임의로 성공 처리하지 않는다.

## 12. Codex 작업 지침

- 코드는 기능별 모듈로 분리한다.
- 기존 동작을 유지하면서 단계적으로 구현한다.
- 매 단계가 완료되면 자동 테스트를 실행한다.
- 실제 하드웨어 테스트 결과를 추측하지 않는다.
- COM 포트, 모니터 ID, GPIO는 설정 가능하게 만든다.
- 운영체제 전원 제어 코드는 별도 모듈로 분리한다.
- 센서가 응답하지 않으면 화면을 자동으로 끄지 않는다.
- 사용자 입력과 충돌하는 자동화는 피한다.
- 센서 로그와 프로그램 로그를 구분한다.
- 테스트를 위해 가상 센서 데이터를 주입하는 시뮬레이션 모드를 제공한다.
- 개발 단계별 결과를 README와 개발 로그에 기록한다.

**가장 먼저 Phase 1을 구현한다.**

실제 MCU 없이 Windows 프로그램에서 모니터 밝기 조절, 화면 OFF, 화면 ON을 테스트한 뒤, 정상 작동이 확인되면 펌웨어 개발로 진행한다.
